    How it works

    Peel the onion, one trusted hop at a time

    Onion routing separates who you are from what you say. Each relay learns only the previous and next hop, never the whole path or the message.

    Cryptographic building blocks

    PyCryptodome
    AES-256-GCM AEAD
    Every onion layer and the end-to-end message use 256-bit keys with a 96-bit nonce and a 128-bit authentication tag. A modified byte fails authentication.
    RSA-3072 · OAEP-SHA-256 key transport
    Each one-time AES session key is wrapped with the recipient's public key. Only the holder of the matching private key can unwrap it.
    Domain separation AAD
    Associated data binds each ciphertext to its protocol version, domain (onion or e2e), and recipient key ID.
    Replay defence stateful
    Each relay stores a SHA-256 digest of accepted packets for {{ replay_ttl_seconds }} seconds. A duplicate is rejected with HTTP 409.
    Trusted next hops allowlist
    Decrypted instructions contain logical IDs only. A local registry maps them to endpoints, so packet data cannot trigger an SSRF request.

    Design trade-offs

    honest limits
    • Three fixed relays. The demo uses a static path for clarity; a real network needs path selection, diversity, and churn handling.
    • Timing and size leakage. Packet sizes shrink at each hop and timing can correlate traffic. Production systems use fixed-size cells and cover traffic.
    • No sender authentication. Bob knows the message is authentic as ciphertext, but not who sent it. A signature or anonymous credential layer would be needed.
    • Endpoint trust. Compromising Alice or Bob exposes plaintext. Onion routing protects the path in between, not the endpoints.
    • Single-process hosting. The hosted demo runs all services in one process for free deployment; the request/relay code paths still use real HTTP semantics.

    Key lifecycle: rotate, revoke, test i

    grace {{ key_grace_seconds }} s

    Rotate gives a service a fresh key pair. The old key stays retired for a short grace period so packets already in flight still arrive, then becomes expired and its private key is destroyed. Revoke marks a key revoked at once, for example when it may have been stolen. Revoking an active key generates a replacement automatically, so the circuit keeps working. Send test onion builds a real packet that uses that exact key, so you can watch each hop accept or reject it.
